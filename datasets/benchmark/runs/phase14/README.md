# Phase 14 Controlled Runtime Evaluation

## Purpose

This directory contains controlled execution definitions, runtime evidence, evaluation results, benchmark records, and quality-gate documentation for Phase 14.

It operationalizes the approved evaluation/benchmark definitions using the supported platform adapters without redefining QA-AI semantics.

## Boundary

This directory may contain approved execution definitions, runtime prompts, capture templates, captured outputs, criterion-level evaluations, benchmark records, comparisons, and approved baseline references. It must not contain fabricated runtime outputs, invented scores, or placeholder files presented as measured evidence.

## Pilot Run Set

- Dataset: `REQ-AUTH-001`
- Artifact: Structured Test Case Model generated by `workflows/testcase-generation`
- Platforms: ChatGPT, Claude, Cursor
- Criteria: `EVAL-CRITERIA-001`
- Rubric: `EVAL-RUBRIC-001`
- Scoring: `EVAL-SCORING-001`
- Baseline definition: `BENCH-BASELINE-001`

The dataset is intentionally simple and fully specified. It measures a narrow pilot scope, not the entire QA-AI framework.

## Historical status interpretation

The per-platform `Baseline-Candidate.json` records preserve the status at the time they were captured. Their Candidate labels are historical evidence and should not be edited to rewrite the record of the original gate. The current aggregate status and review hold are defined in `Benchmark-Status-Register.md`.

## Evidence integrity

- ChatGPT pre-fix runs remain retained as regression evidence.
- The prior Claude runtime-availability condition is preserved in `Claude-Runtime-Blocker.md`; the later controlled run and evaluation evidence resolved that blocker.
- Raw runtime output must remain unchanged. Corrections to evaluations must be versioned and linked to the original evidence.
- Missing runtime metadata must remain explicitly unknown; never reconstruct it by guessing.
