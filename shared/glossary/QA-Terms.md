# QA Terms

## Purpose

This document defines standardized terminology related to software quality assurance and testing.

Its purpose is to establish a shared vocabulary across the QA-AI framework, ensuring that documentation, skills, workflows, templates, and other artifacts use consistent terminology.

---

## A

### Acceptance Criteria

**Definition**

Conditions that must be satisfied before a requirement, user story, or feature is considered complete and acceptable.

**Related Terms**

- Requirement
- User Story
- Validation

---

## B

### Black Box Testing

**Definition**

A testing approach that evaluates system behavior without knowledge of the internal implementation.

**Related Terms**

- White Box Testing
- Gray Box Testing
- Functional Testing

---

### Boundary Value Analysis (BVA)

**Definition**

A black-box testing technique that verifies behavior at the boundaries of valid input ranges.

**Related Terms**

- Boundary Testing
- Equivalence Partitioning

---

### Bug

**Definition**

A defect in software that causes the actual behavior to differ from the expected behavior.

**Related Terms**

- Defect
- Issue
- Incident

---

## D

### Defect

**Definition**

A flaw in a software product that may cause incorrect or unexpected behavior.

**Related Terms**

- Bug
- Failure
- Incident

---

## E

### End-to-End (E2E) Testing

**Definition**

A testing approach that verifies complete business workflows across integrated systems.

**Related Terms**

- Integration Testing
- System Testing

---

### Equivalence Partitioning (EP)

**Definition**

A black-box testing technique that divides input data into equivalent groups expected to behave similarly.

**Related Terms**

- Boundary Value Analysis
- Test Data

---

## F

### Functional Testing

**Definition**

Testing performed to verify that software functions behave according to specified requirements.

**Related Terms**

- Requirement
- System Testing

---

## I

### Integration Testing

**Definition**

Testing performed to verify interactions between integrated components or systems.

**Related Terms**

- System Testing
- API Testing

---

### Issue

**Definition**

A general term describing a problem, concern, or observation identified during development or testing.

**Related Terms**

- Bug
- Defect
- Incident

---

## N

### Non-Functional Testing

**Definition**

Testing performed to evaluate quality attributes such as performance, security, usability, or reliability.

**Related Terms**

- Performance Testing
- Security Testing

---

## P

### Performance Testing

**Definition**

Testing performed to evaluate system responsiveness, stability, scalability, or resource utilization under workload.

**Related Terms**

- Load Testing
- Stress Testing

---

### Positive Testing

**Definition**

Testing performed using valid inputs and expected user behavior.

**Related Terms**

- Negative Testing
- Functional Testing

---

## R

### Regression Testing

**Definition**

Testing performed to verify that existing functionality continues to work after changes have been introduced.

**Related Terms**

- Smoke Testing
- Retesting

---

### Retesting

**Definition**

Testing performed to verify that a reported defect has been fixed successfully.

**Related Terms**

- Regression Testing
- Defect

---

## S

### Sanity Testing

**Definition**

A focused testing activity performed to verify that specific changes function correctly before broader testing begins.

**Related Terms**

- Smoke Testing
- Regression Testing

---

### Smoke Testing

**Definition**

A preliminary testing activity performed to verify that the most critical functions of a build operate correctly.

**Related Terms**

- Sanity Testing
- Regression Testing

---

### System Testing

**Definition**

Testing performed on the complete integrated system to verify compliance with specified requirements.

**Related Terms**

- Integration Testing
- Acceptance Testing

---

## T

### Test Case

**Definition**

A documented set of preconditions, test steps, test data, and expected results used to verify a specific objective.

**Related Terms**

- Test Scenario
- Test Data

---

### Test Data

**Definition**

The input information required to execute one or more test cases.

**Related Terms**

- Test Case
- Boundary Value Analysis

---

### Test Scenario

**Definition**

A high-level description of a business situation or workflow to be verified through testing.

**Related Terms**

- Test Case
- Requirement

---

### Test Suite

**Definition**

A collection of related test cases executed together for a common testing objective.

**Related Terms**

- Test Case
- Regression Testing

---

## U

### User Acceptance Testing (UAT)

**Definition**

Testing performed by business users or customer representatives to confirm that the solution satisfies business needs.

**Related Terms**

- Acceptance Criteria
- System Testing

---

## W

### White Box Testing

**Definition**

A testing approach that verifies software behavior based on knowledge of the internal implementation.

**Related Terms**

- Black Box Testing
- Gray Box Testing
